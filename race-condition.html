Race Condition

A race condition can happen when two requests read or update the same state at the same time. In this example, two requests can both see an unused coupon and apply it before either records that it was used.

  • OWASP A06:2025 Insecure Design
  • CWE-362

Try it

The cart starts at $100. Coupon LAB10 takes off $10 once. This deterministic client-side concurrency model interleaves requests step by step; it does not reproduce real database concurrency or send server requests. Every run starts with a fresh cart.

Why it matters

A race can break limits on coupons, transfers, or verification.

Real-world case · GitLab email verification

A PortSwigger researcher sent two email-change requests to GitLab at the same time. A confirmation message sent to the researcher’s inbox could verify a different address. This disclosed finding shows how overlapping requests can interfere with shared state, as they do in the coupon lab.
